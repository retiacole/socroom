# SOCroom v0.5.1

[すぐにやってみる / Play Now](https://retiacole.github.io/socroom/) · [オフライン用HTML / Offline HTML](https://github.com/retiacole/socroom/blob/main/socroom.html)

<img src="docs/images/socroom-character.png" align="right" width="120" alt="青い盾と剣を持つSOCroomのキャラクター">

**証拠を見極め、次の一手を選ぶ。**<br>
*Assess the evidence. Choose the next step.*

ブラウザだけで、SOCアナリストの一次対応を体験する演習室です。操作チュートリアル専用1問、ガイド付き実務演習5問、低・中・高それぞれ異なる5問、合計21問を収録しています。難易度を変えると、調査する問題そのものが変わります。仮想シェルは [Logroom](https://github.com/retiacole/logroom) のMITライセンスの実装を基にしています。

<br clear="right">

## v0.5.1の修正

- 「複数端末へのサービス登録」は、配布完了一覧と監視復旧の両方を主証拠として確認してから完了します。
- 中断中のチュートリアルを保存ファイルで置き換える前に、確認と旧進捗の書き出しができます。
- 生ログの展開状態とキーボードの操作位置を、証拠追加・案件到着後も保持します。
- 照会したすべての質問を「回答待ち」と返信到着の表示に反映します。
- 仮想端末の `rg` で `\d`・`\D` を使った検索を修正しました。

## v0.5の主な変更

ログの見出しから調査の結論が分からないようにし、収集できない情報は収集設定の資料に移しました。作業票には承認した範囲を記載し、担当者の部分的な回答とログを自分で照合します。判定と主対応の組み合わせを増やし、主証拠の絞り込み、照会の質問選択、アカウント・アプリの対象指定、端末からの証拠登録を追加しました。

通常イベントは低50行・中100行・高180行を各ケースに追加しています。実務演習はガイド付き2件では追加せず、チェックリスト2件は各50行、自走1件は75行です。操作チュートリアルは操作の習得に集中できる量を維持しています。

## 開く

**オンライン**なら [Play Now](https://retiacole.github.io/socroom/) を開くと、そのまま練習できます。

**オフライン**で使う場合：

1. [socroom.html](https://github.com/retiacole/socroom/blob/main/socroom.html) を開き、右上の **Download raw file** で保存します。リポジトリ全体を **Code → Download ZIP** で保存して展開する方法も使えます。
2. 保存した **`socroom.html`** をChrome、Edge、Firefox、SafariなどのJavaScriptを実行できるブラウザで開きます。

ダウンロード後は、ブラウザだけでローカルに完結します。インストール、Node.js、ローカルサーバー、アカウントは不要です。オンライン版を開くときにはインターネット接続が必要ですが、ダウンロードしたHTMLはオフラインで使えます。GitHub上でHTMLのソースを表示するのではなく、保存したファイルを開いてください。ブラウザごとの実画面・互換性は未検証です。

Choose **Play Now** to start in your browser, or download the HTML file with **Download raw file** for offline use.

オンライン版と保存したHTMLでは、自動保存の領域が異なります。進捗を移すときは、元の画面で「保存」からJSONを書き出し、移動先の「読込」で読み込んでください。

Online and local files use separate browser saves. To transfer progress, export a JSON save in the original app and import it in the other one.

## はじめての操作チュートリアル

ホームの「操作チュートリアルを始める」から始めます。通常勤務の途中では、上部の「ガイド」からも開始できます。

検証環境への接続先が増えた専用案件を使い、21ステップで、依頼の確認 → ログ検索と生ログ → 証拠の追加 → 資料の照合 → 担当者への照会 → 判定・対応・報告の記録を体験します。

- 上の案内には「どこを押すか」「何のための操作か」「操作の結果」を表示します。
- 緑の枠とゆっくりした点滅で次の操作場所を強調します。操作が完了すると「次へ」が有効になり、点滅も移ります。端末の「視差効果を減らす」などの設定では点滅を止め、枠で表示します。
- 「前へ」で説明を読み直せます。「操作場所を表示」で別のタブから操作対象へ戻れます。
- 報告文には、その欄だけに挿入できる入力例を用意しています。
- 時間制限はなく、照会はすぐに返信されます。経過時間によるゲームオーバーはありません。
- 「中断して勤務選択へ」で中断でき、ホームの「チュートリアルの続きから」で再開できます。「始める」は最初からの練習です。
- 通常勤務は一時停止して保持します。チュートリアルとは別の保存領域を使うので、案件・証拠・下書き・仮想端末の作業ファイルは置き換わりません。

チュートリアル中の「保存」は手順の位置もJSONへ含めます。このファイルの「読込」はチュートリアルを再開し、通常勤務の保存ファイルは従来どおり読み込めます。

## ガイド付き実務演習

ホームの「ガイド付き実務演習を始める」から、5件の専用ケースを1件ずつ進めます。SOCroom-easyで個々の操作を学んだ後に、「何を調べるか → 証拠を残す → 判断と報告」をつなげる練習です。操作に迷う場合は、先に操作チュートリアルを使えます。

| 演習 | 支援 | 学ぶこと |
| --- | --- | --- |
| 1〜2件目 | 次の行動と、その理由を表示。操作場所を枠とゆっくりした点滅で案内 | ログの事実を別の資料・担当者の回答と照合し、根拠付きで報告する |
| 3〜4件目 | 調査のチェックリストだけを表示。順番は自分で決める | 必要な作業を組み立て、確認できないことを引き継ぐ |
| 5件目 | 目標を示し、手順の案内を外す | 自分の判断で1件の調査と報告を完了する |

- 全5件とも時間制限なし。経過時間は参考表示で、時間切れによるゲームオーバーはありません。照会も即時返信です。
- 正当な業務、インシデント、証拠不足で判断保留となる案件を含みます。通常勤務や操作チュートリアルとは別問題です。
- ガイドは調べ方を示しますが、判定や報告文を自動入力しません。証拠と判断は自分で選びます。
- チェックは操作の実施を示すもので、結論が正しいという意味ではありません。判定・対応・根拠の組み合わせは提出時に確認します。
- 各件の提出後に、自分の報告と報告例、根拠、未確認事項、次の対応を見比べます。比較したことを確認してから次のケースへ進みます。「事実／分からないこと／次の対応」の3欄で振り返りを任意に記録でき、保存・再開にも引き継ぎます。文章の意味や品質は自動採点しません。
- 「中断して勤務選択へ」と「実務演習の続きから」で再開できます。実務演習専用の保存領域を使い、通常勤務や操作チュートリアルの進捗・作業ファイルを保持します。
- 「保存」では現在の演習、案内の位置、完了済みケースの記録をJSONに含めます。5件を終えると難易度「低」の勤務選択へ戻ります。「最初から」は確認画面で実務演習だけをリセットします。

## 通常の勤務

1. 難易度を選ぶと、その難易度専用の5問が表示されます。
2. 一勤務（5問）またはケース単独練習を選び、「5問のシフトを開始」または「この1問を開始」を押します。
3. アラート、ログ、資産・資料を読み、必要なら担当者に照会します。
4. 関連するログ、文書、返信を「証拠に追加」します。
5. 判定・優先度・対象・対応を選び、確認した事実と引き継ぎ事項を記録します。
6. 全ケースの必要な初動を完了すると、勤務の振り返りが表示されます。

## 難易度

| 難易度 | 問題数・調査内容 | 案件の到着 | 初動期限 | 支援 |
| --- | --- | --- | --- | --- |
| 低・基礎監視 | 専用5問。直接的な証拠と通常イベント50行を照合 | 1件ずつ。対応完了後に次の案件 | なし | 段階ヒント、即時返信 |
| 中・照合調査 | 専用5問。複数ログと通常イベント100行、業務の確認を組み合わせる | 5件同時 | 各案件の到着から20分 | 2段階ヒント、時間差の返信 |
| 高・影響調査 | 専用5問。通常イベント180行から影響範囲と証拠の限界を判断 | 45秒ごとに追加（0・45・90・135・180秒） | 各案件の到着から15分 | ヒントなし、返信までの時間が長い |

通常の15問・実務演習5問・チュートリアルに同じ問題はありません。難易度間で端末名やIPだけを変えた同一問題も使っていません。複数端末の問題では「時系列」に案件に属する各端末のログを表示します。「この端末を検索」は主対象の1台に絞る操作なので、他端末も調べるときは絞り込みを解除してください。対応記録では、守るべき主な対象を端末・アカウント・アプリから選びます。認証サービスに出たログでも、対処の対象は利用者アカウントや連携アプリになることがあります。関連する対象への影響は本文に記録します。

重要案件の初動が期限内に完了しないとゲームオーバーです。正当な業務などの案件は、期限を超えても勤務を続けられますが、終了時の評価に遅延が記録されます。時間は教材用の設定であり、現実のSOCのSLAを示すものではありません。

計測するのは勤務の操作時間です。一時停止、ガイド・状況・ヒント表示中、別タブ表示中、保存して閉じている間は停止します。自動停止からの復帰は手動です。「次の更新へ進む」は待ち時間を早送りする操作で、進めた時間は期限にも含まれます。更新がない場合は30秒進みます。

ログに書かれた発生時刻はすべてUTCで、勤務経過時間とは別です。高難易度には案件到着後に届くログもあります。担当者の回答、追加案件、追加ログは、到着するまでGUIと端末のどちらでも閲覧・証拠登録できません。

ゲームオーバー後は、期限の3分前から再挑戦するか、時間制限なしの復習へ移れます。再挑戦は直近の提出・照会を巻き戻し、下書きを保持します。以前の試行は履歴に残ります。復習でのクリアは通常クリアと区別されます。

## 調査ツール

- **ログ検索**：文字列、ソース、端末、UTCの開始・終了時刻で絞り込み。生ログと形式ラベルを表示できます。IP・ユーザー名はクリックで検索できます。通常イベントが混在するため、識別子や時刻で絞り込んで調べます。
- **資産・資料**：資産台帳、変更申請、ログ収集状況などを照合します。
- **時系列**：選んだ案件のログを発生順に確認します。検索・ソース・端末・時刻の条件を使い、関連する流れを追えます。
- **端末**：`grep`、`awk`、`sed`、`jq` などを使う仮想シェル。`help` と `help コマンド名` で対応構文を確認できます。
- **照会**：通常勤務では複数の質問から選びます。質問の具体性によって得られる回答が異なり、各質問を個別に依頼できます。担当者の回答だけで結論を決めず、ログと資料を照合します。操作チュートリアルと実務演習は案内に合わせた照会を使います。

ターミナルの原本ログと資料は参照専用です。作業ファイルは `/home/analyst` 内に作れます。実OS、ネットワーク、ユーザーのPC上のファイルにはアクセスしません。GUIと端末は同じ公開済みデータを参照します。`grep -n` で原本の行番号を確認し、`evidence /var/log/対象ファイル:行番号` で現在の案件の主証拠に追加できます。コピー・編集した作業ファイルは登録できません。追加ログは原本の末尾へ追記するため、既存行の番号は変わりません。時刻順に並べ直すときはパイプや作業用コピーを使います。vi・view・slは未対応です。

## 生ログの形式

GUIのソース・ユーザー・IPなどは検索用の正規化項目です。収集元が識別できない値は空欄で表示し、すべての記録に端末や利用者を補うことはしません。生ログにはWindows Security XML、Entra監査JSON、M365監査JSONを参考にした合成例と、SOCroom独自のJSONを使用しています。通常イベントにはOpenSSHのsyslogやnginx combined形式の例も含みます。画面の形式ラベルで区別できます。

製品の全フィールド・全バージョンを再現したログではありません。省略や教材用の属性があります。特に「SOCroom JSON」は製品固有の生ログ形式ではなく、架空のサービス・収集記録です。ファイル名だけを基に現実の製品の形式を覚えないよう、形式ラベルと収集資料を合わせて参照してください。

形式の参考資料：[Windowsイベント4720](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4720)、[Entra SigninLogsの列](https://learn.microsoft.com/en-us/azure/azure-monitor/reference/tables/signinlogs)、[nginxアクセスログ設定](https://nginx.org/en/docs/http/ngx_http_log_module.html)。

仮想シェルは学習用の部分実装です。`~`、`2>/dev/null`、awkの文字列連結を使えます。`grep`・`grep -E` の `\d`・`\D` は未対応として明示し、数字には `[0-9]` または `[[:digit:]]` を使います。`rg` では `\d`・`\D` をファイル検索とパイプ入力の両方で使えます。シェル変数展開、コマンド置換、任意のプログラム実行、完全なGNU互換は提供しません。`sudo` もブラウザ内の模擬機能であり、SOCroomの原本は昇格しても変更できません。対応範囲は `help コマンド名` で確認してください。

## 判定と学習の範囲

悪性の操作、正当な業務、証拠不足の案件が含まれます。判定、優先度、主な対象、次の対応をそれぞれ判断します。正当でも再発への追加監視が必要なケース、未確定でも事前承認された保護措置を依頼するケース、確定した侵害を権限のある担当者へ引き継ぐケースがあります。対応欄では直ちに行う主対応を一つ選び、並行する連絡や追加調査は報告に記載します。

主証拠にはケースごとの提出上限があり、必要な独立した根拠と、絞り込みの両方を評価します。全件登録では完了できません。余分な根拠を外しても調査した事実はなくならないので、補足は報告文へ残してください。

自由記述は、事実欄に対象・識別子・証拠ID・時刻のいずれか、引継ぎ欄に担当者や責任者などの依頼先があるかを確認します。文章の意味・正確性・品質の採点ではありません。振り返りの報告例と比較してください。実際の端末隔離・メール送信などは行わず、選択した対応を模擬的に記録します。各案件のアラートは1件に集約して提示しており、複数アラートを別のインシデントへ統合する操作は未搭載です。

すべての人物・組織・ログは架空の教材です。実際のサービスの画面やクエリ言語を完全再現するものではありません。

## 保存と再開

v0.5はv0.3・v0.4の保存ファイルを読み込み、新しい教材・採点基準で再評価します。保存済みの証拠・下書き・仮想作業ファイルを引き継ぎます。変更の影響で完了条件を満たさなくなった案件は再調査になり、その勤務は一時停止・時間制限なしで見直せます。古い点数をそのまま新しい評価として扱いません。

実務演習は最初に見直しが必要になったケースへ戻ります。それより後のケースの記録も保管し、順番に再開します。振り返りのメモを含め、通常勤務・操作チュートリアル・実務演習の保存領域は分離したままです。

v0.3では問題構成を変更したため、v0.2 とは別の保存領域を使います。以前の自動保存は削除しません。ホームに「前の版の進捗が残っています」と表示された場合は、そこから旧版用のJSONを取り出せます。v0.2の保存ファイルは、旧版の `socroom-v0.2.html` で読み込んでください。新旧の問題を混ぜて復元することはできません。

- **保存**：進捗、証拠、判断、操作履歴、仮想作業ファイルをJSONへ書き出します。
- **読込**：保存したJSONを選び、通常勤務は停止状態から再開します。チュートリアルとガイド付き実務演習の保存ファイルは、それぞれの演習を再開します。
- **報告を書き出す**：勤務完了またはゲームオーバーの画面から、証拠と記録をテキストで保存します。

自動保存にはlocalStorageを使いますが、ローカルHTMLの保存挙動はブラウザや設定に依存します。重要な進捗はJSONファイルに保存してください。ブラウザデータの消去やファイルの移動では自動保存が引き継がれない場合があります。保存ファイルのバージョン・ケース・証拠・時刻は読み込み時に検証します。

## 開発

通常のビルドはルートの配布HTMLと、GitHub Pages用の `docs/index.html`・`docs/socroom.html` を同じ内容で生成します。公開元は `main` ブランチの `/docs` です。

利用者には不要ですが、ソースからのビルドとエンジン・端末テストにはNode.js 22以降を使います。HTMLを含まないソース専用ZIPから始める場合も、次の `node build.js` で `socroom.html` を生成できます。

```sh
node build.js
node --test tests/engine.test.js tests/terminal.test.js tests/tutorial.test.js tests/bridge.test.js tests/release.test.js
```

`build.js`は`content/*.json`を`assemble-data.js`と`prepare-data.js`で`src/data.js`へ組み立て、`src/`の各モジュールを単一HTMLへ埋め込みます。教材の編集元は`content/`です。`prepare-data.js`は収集元に沿った表示項目・生ログ形式と、決定的に生成する通常イベントを付加します。外部CSS、フォント、JavaScript、JSONの実行時ロードはありません。CSPの `connect-src 'none'` を設定しています。

DOM操作テストには開発時のみjsdom 26.1.0を使います。`SOCROOM_JSDOM_MODULE` に既存jsdomモジュールの絶対パスを指定することもできます。

```sh
npm ci
npm test
```

エンジン・端末・チュートリアル・実務演習の全5件の完了・段階的な案内・進捗分離・JSON再開・DOMの操作処理を検証しています。実ブラウザでの描画、ダウンロード、各ブラウザのfile://保存挙動の検証は未実施です。

### 採点とデータ生成の仕様

内部データ版は `socroom-3` です。主証拠の提出上限は既定で必要な証拠群の数＋2件です。独立した証拠群を満たす割合に20点、上限内に絞ることに10点を配分します。上限超過では案件を完了できません。根拠を探している間は一時的に多く登録できます。自由記述の検査は具体的情報と依頼先の形式確認だけです。詳細な保存・採点契約は `CONTRACT.md` を参照してください。

### Logroomのシェルを同期する

現在の取り込み元は [`6d54626138261b9756d959050bca8fe29d1d9181`](https://github.com/retiacole/logroom/commit/6d54626138261b9756d959050bca8fe29d1d9181) です。ソースURL・コミット・SHA-256を `scripts/logroom-source.json` とvendorヘッダーに記録しています。同期時の変更はCommonJS／ShellErrorの公開です。`grep` と `rg` の数字クラスの扱いは上流実装を保持し、同期時に互換性の確認箇所を検証します。原本保護や証拠登録は別ファイルのアダプターに残します。

現在の版を再生成する場合：

```sh
mkdir -p work/upstream
curl --fail --location https://raw.githubusercontent.com/retiacole/logroom/6d54626138261b9756d959050bca8fe29d1d9181/src/shell.js --output work/upstream/logroom-shell.js
node scripts/sync-logroom.js work/upstream/logroom-shell.js 6d54626138261b9756d959050bca8fe29d1d9181
node --test tests/terminal.test.js
npm test
node build.js
```

新しい版を取り込むときは、URLと引数を同じ固定コミットへ変更します。同期スクリプトが実装の目印の変更を検出した場合は、その場で停止します。手作業で通過させる前に差分を確認し、原本保護・権限昇格・リダイレクト・証拠登録のテストを実施してください。ダウンロードが必要なのは開発時の同期だけです。
