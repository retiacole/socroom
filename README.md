# SOCroom v0.4

ブラウザだけで、SOCアナリストの一次対応を体験する演習室です。操作チュートリアル専用1問、ガイド付き実務演習5問、低・中・高それぞれ異なる5問、合計21問を収録しています。難易度を変えると、調査する問題そのものが変わります。仮想シェルは [Logroom](https://github.com/retiacole/logroom) のMITライセンスの実装を基にしています。

## 開く

1. このGitHubページの **Code → Download ZIP** から一式をダウンロードします。
2. ZIPファイルを展開します。
3. 展開したフォルダー内の **`socroom.html`** をChrome、Edge、Firefox、SafariなどのJavaScriptを実行できるブラウザで開きます。

ダウンロード後は、ブラウザだけでローカルに完結します。アプリの利用にインストール、Node.js、ローカルサーバー、アカウント、インターネット接続は不要です。GitHub上でHTMLのソースを表示するのではなく、展開したファイルを開いてください。ブラウザごとの実画面・互換性は未検証です。

## はじめての操作チュートリアル

ホームの「操作チュートリアルを始める」から始めます。通常勤務の途中では、上部の「ガイド」からも開始できます。

検証環境への接続先が増えた専用案件を使い、21ステップで、依頼の確認 → ログ検索と生ログ → 証拠の追加 → 資料の照合 → 担当者への照会 → 判定・対応・報告の記録を体験します。

- 上の案内には「どこを押すか」「何のための操作か」「操作の結果」を表示します。
- 緑の枠とゆっくりした点滅で次の操作場所を強調します。操作が完了すると「次へ」が有効になり、点滅も移ります。端末の「視差効果を減らす」などの設定では点滅を止め、枠で表示します。
- 「前へ」で説明を読み直せます。「操作場所を表示」で別のタブから操作対象へ戻れます。
- 報告文には、その欄だけに挿入できる入力例を用意しています。
- 時間制限はなく、照会はすぐに返信されます。経過時間によるゲームオーバーはありません。
- 「中断して勤務選択へ」で中断でき、ホームの「チュートリアルの続きから」で再開できます。「始める」は最初からの練習です。
- 通常勤務は一時停止して保持します。チュートリアルとは別の保存領域を使うので、案件・証拠・下書き・仮想端末の作業ファイルは置き換わりません。

チュートリアル中の「保存」は手順の位置もJSONへ含めます。このファイルの「読込」はチュートリアルを再開し、通常勤務の保存ファイルは従来どおり読み込めます。

## ガイド付き実務演習（v0.4で追加）

ホームの「ガイド付き実務演習を始める」から、5件の専用ケースを1件ずつ進めます。SOCroom-easyで個々の操作を学んだ後に、「何を調べるか → 証拠を残す → 判断と報告」をつなげる練習です。操作に迷う場合は、先に操作チュートリアルを使えます。

| 演習 | 支援 | 学ぶこと |
| --- | --- | --- |
| 1〜2件目 | 次の行動と、その理由を表示。操作場所を枠とゆっくりした点滅で案内 | ログの事実を別の資料・担当者の回答と照合し、根拠付きで報告する |
| 3〜4件目 | 調査のチェックリストだけを表示。順番は自分で決める | 必要な作業を組み立て、確認できないことを引き継ぐ |
| 5件目 | 目標を示し、手順の案内を外す | 自分の判断で1件の調査と報告を完了する |

- 全5件とも時間制限なし。経過時間は参考表示で、時間切れによるゲームオーバーはありません。照会も即時返信です。
- 正当な業務、インシデント、証拠不足で判断保留となる案件を含みます。通常勤務や操作チュートリアルとは別問題です。
- ガイドは調べ方を示しますが、判定や報告文を自動入力しません。証拠と判断は自分で選びます。
- チェックは操作の実施を示すもので、結論が正しいという意味ではありません。判定・対応・根拠の組み合わせは提出時に確認します。
- 各件の提出後に、自分の報告と報告例、根拠、未確認事項、次の対応を見比べます。比較したことを確認してから次のケースへ進みます。文章の意味や品質は自動採点しません。
- 「中断して勤務選択へ」と「実務演習の続きから」で再開できます。実務演習専用の保存領域を使い、通常勤務や操作チュートリアルの進捗・作業ファイルを保持します。
- 「保存」では現在の演習、案内の位置、完了済みケースの記録をJSONに含めます。5件を終えると難易度「低」の勤務選択へ戻ります。「最初から」は確認画面で実務演習だけをリセットします。

## 通常の勤務

1. 難易度を選ぶと、その難易度専用の5問が表示されます。
2. 一勤務（5問）またはケース単独練習を選び、「5問のシフトを開始」または「この1問を開始」を押します。
3. アラート、ログ、資産・資料を読み、必要なら担当者に照会します。
4. 関連するログ、文書、返信を「証拠に追加」します。
5. 判定・優先度・対象・対応を選び、確認した事実と引き継ぎ事項を記録します。
6. 全ケースの必要な初動を完了すると、勤務の振り返りが表示されます。

## 難易度

| 難易度 | 問題数・調査内容 | 案件の到着 | 初動期限 | 支援 |
| --- | --- | --- | --- | --- |
| 低・基礎監視 | 専用5問。単一端末の直接的な証拠を照合 | 1件ずつ。対応完了後に次の案件 | なし | 段階ヒント、即時返信 |
| 中・照合調査 | 専用5問。複数ログと業務の確認を組み合わせる | 5件同時 | 各案件の到着から20分 | 段階ヒント、時間差の返信 |
| 高・影響調査 | 専用5問。複数端末への広がり、証拠の限界、業務影響を判断 | 45秒ごとに追加（0・45・90・135・180秒） | 各案件の到着から15分 | ヒントなし、返信までの時間が長い |

通常の15問・実務演習5問・チュートリアルに同じ問題はありません。難易度間で端末名やIPだけを変えた同一問題も使っていません。複数端末の問題では「時系列」に案件に属する各端末のログを表示します。「この端末を検索」は主対象の1台に絞る操作なので、他端末も調べるときは絞り込みを解除してください。対応記録の対象端末には案件の主対象を選び、関連端末と判明した影響は本文に記録します。

重要案件の初動が期限内に完了しないとゲームオーバーです。正当な業務などの案件は、期限を超えても勤務を続けられますが、終了時の評価に遅延が記録されます。時間は教材用の設定であり、現実のSOCのSLAを示すものではありません。

計測するのは勤務の操作時間です。一時停止、ガイド・状況・ヒント表示中、別タブ表示中、保存して閉じている間は停止します。自動停止からの復帰は手動です。「次の更新へ進む」は待ち時間を早送りする操作で、進めた時間は期限にも含まれます。更新がない場合は30秒進みます。

ログに書かれた発生時刻はすべてUTCです。初版のログは着信時に提供される過去の記録で、勤務経過時間とは別です。担当者の回答と高難易度で追加される案件は、到着するまで閲覧・証拠登録できません。

ゲームオーバー後は、期限の3分前から再挑戦するか、時間制限なしの復習へ移れます。再挑戦は直近の提出・照会を巻き戻し、下書きを保持します。以前の試行は履歴に残ります。復習でのクリアは通常クリアと区別されます。

## 調査ツール

- **ログ検索**：文字列、ソース、端末で絞り込み。生ログも表示できます。IP・ユーザー名はクリックで検索できます。
- **資産・資料**：資産台帳、変更申請、ログ収集状況などを照合します。
- **時系列**：選んだ案件のログを発生順に確認します。
- **端末**：`grep`、`awk`、`sed`、`jq` などを使う仮想シェル。`help` と `help コマンド名` で対応構文を確認できます。
- **照会**：架空の担当者への確認を依頼し、回答を証拠として利用します。

ターミナルの原本ログと資料は参照専用です。作業ファイルは `/home/analyst` 内に作れます。実OS、ネットワーク、ユーザーのPC上のファイルにはアクセスしません。GUIと端末は同じ公開済みデータを参照します。端末から直接証拠登録はできないため、ログ検索または資料画面で追加してください。vi・view・slは初版では未対応です。

## 判定と学習の範囲

悪性の操作、正当な業務、証拠不足の案件が含まれます。初版では、判定、許容される優先度と対応、対象、独立した根拠の組み合わせをルールで評価します。複数の適切な対応・同等の証拠を許容するケースがあります。

自由記述は記入の有無のみ確認し、文章の意味・正確性・品質は自動採点しません。振り返りの報告例と比較してください。実際の端末隔離・メール送信などは行わず、選択した対応を模擬的に記録します。各ケースのアラートは初版では1件に集約して提示しており、複数アラートを別のインシデントへ統合する操作は未搭載です。

すべての人物・組織・ログは架空の教材です。実際のサービスの画面やクエリ言語を完全再現するものではありません。

## 保存と再開

v0.4はv0.3の通常勤務・操作チュートリアルの保存形式と問題を維持しています。同じ場所のHTMLを更新する場合は既存の自動保存を利用でき、v0.3で書き出したJSONも読み込めます。ガイド付き実務演習は独立した保存領域を追加しています。

v0.3では問題構成を変更したため、v0.2 とは別の保存領域を使います。以前の自動保存は削除しません。ホームに「前の版の進捗が残っています」と表示された場合は、そこから旧版用のJSONを取り出せます。v0.2の保存ファイルは、旧版の `socroom-v0.2.html` で読み込んでください。新旧の問題を混ぜて復元することはできません。

- **保存**：進捗、証拠、判断、操作履歴、仮想作業ファイルをJSONへ書き出します。
- **読込**：保存したJSONを選び、通常勤務は停止状態から再開します。チュートリアルとガイド付き実務演習の保存ファイルは、それぞれの演習を再開します。
- **報告を書き出す**：勤務完了またはゲームオーバーの画面から、証拠と記録をテキストで保存します。

自動保存にはlocalStorageを使いますが、ローカルHTMLの保存挙動はブラウザや設定に依存します。重要な進捗はJSONファイルに保存してください。ブラウザデータの消去やファイルの移動では自動保存が引き継がれない場合があります。保存ファイルのバージョン・ケース・証拠・時刻は読み込み時に検証します。

## 開発

利用者には不要ですが、ソースからのビルドとエンジン・端末テストにはNode.js 22以降を使います。HTMLを含まないソース専用ZIPから始める場合も、次の `node build.js` で `socroom.html` を生成できます。

```sh
node build.js
node --test tests/engine.test.js tests/terminal.test.js tests/tutorial.test.js tests/bridge.test.js tests/release.test.js
```

`build.js`は`content/*.json`を`assemble-data.js`で`src/data.js`へ組み立て、`src/`の各モジュールを単一HTMLへ埋め込みます。教材の編集元は`content/`です。外部CSS、フォント、JavaScript、JSONの実行時ロードはありません。CSPの `connect-src 'none'` を設定しています。

DOM操作テストには開発時のみjsdom 26.1.0を使います。`SOCROOM_JSDOM_MODULE` に既存jsdomモジュールの絶対パスを指定することもできます。

```sh
npm ci
npm test
```

エンジン・端末・チュートリアル・実務演習の全5件の完了・段階的な案内・進捗分離・JSON再開・DOMの操作処理を検証しています。実ブラウザでの描画、ダウンロード、各ブラウザのfile://保存挙動の検証は未実施です。
